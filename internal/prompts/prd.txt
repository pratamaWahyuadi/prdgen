6.5 Security: [PASTE hasil Security Auditor di sini, elaborate. Pertahankan
   struktur Severity per item. WAJIB pertahankan ID stabil (T1, T2, T3, ...)
   APA ADANYA saat elaborasi -- jangan direnumber, jangan dihilangkan,

7. Tech Stack & Justifikasi (WAJIB berdasarkan jawaban user di hasil
   discovery -- bahasa, database, dan pendekatan akses data/ORM harus
   sesuai yang user sebutkan. Kalau user eksplisit bilang "bebas"/"terserah"
   untuk sebuah keputusan dan discovery TIDAK berhasil menggali preferensi
   lebih jauh, kamu boleh merekomendasikan pilihan sendiri -- tapi WAJIB
   tandai dengan jelas sebagai "🔶 Asumsi (belum dikonfirmasi user)" di
   baris itu, jangan disamarkan seolah itu keputusan yang sudah pasti.

   Sub-section WAJIB "Koneksi & Driver Database" di dalam section ini,
   pin sampai level konkret: nama package/driver persis (contoh: "pgx/v5
   native pool, BUKAN database/sql"), dan strategi instantiation-nya
   ("SATU *pgxpool.Pool dibuat sekali saat startup, di-inject ke semua
   repository lewat constructor -- dilarang membuat pool/koneksi baru di
   file lain"). Sumber nilai: hasil deep-dive user (prioritas pertama),
   atau defaults.yaml (kalau user skip -- kutip VERBATIM). Kalau keduanya
   tidak ada, isi dengan asumsi paling aman dan tandai "🔶 Asumsi" --
   JANGAN dibiarkan kosong/implisit, karena baris inilah yang akan dikutip
   verbatim oleh ERD, Coding Plan, dan GitHub Issues supaya tidak ada
   agent lain yang menebak driver sendiri-sendiri.)

   Sub-section WAJIB "Instance Terbagi Lain" (cache client, message queue,
   HTTP client eksternal, migration tool, session store/auth library):
   sebutkan library/package persis dan strategi instance tunggal untuk
   tiap komponen yang relevan dengan project ini, dengan aturan yang sama
   seperti database -- satu instance shared via DI, dilarang instance
   kedua. KHUSUS session store kalau pakai Redis: WAJIB tulis "reuse
   instance cache client yang sama, JANGAN buat client Redis kedua".)

7.5 Asumsi Teknis -- SECTION WAJIB, TIDAK BOLEH KOSONG:
   - Kalau user mengikuti deep-dive (fase 2): tabel semua keputusan
     low-level dari jawaban deep-dive user, kolom: Keputusan | Nilai |
     Status (user-confirmed / [ASSUMED]) | Basis.
   - Kalau user SKIP deep-dive: kutip VERBATIM seluruh isi defaults.yaml
     ke section ini dalam format tabel, dan setiap nilai WAJIB diberi
     flag [ASSUMED] -- tidak ada satu pun nilai default yang boleh
     disamarkan sebagai keputusan user.
   - Tambahkan kalimat penutup section ini PERSIS: "Coding agent yang
     membaca PRD ini WAJIB menghormati semua keputusan di section ini.
     Dilarang membuat pool/driver/instance kedua untuk komponen yang sama
     (database, cache, message queue, HTTP client, migration tool). Kalau
     saat coding ketemu default yang ternyata tidak cocok, agent harus
     STOP dan bertanya ke user, bukan improvise."
