FASE 1 WAJIB memuat TIGA step eksplisit berikut (nama tool/library
PERSIS dari PRD, bukan versi generic):

1. "Setup Koneksi Database (Single Source of Truth)" yang menyebutkan
   PERSIS: nama file tempat pool/koneksi diinisialisasi (contoh di Go:
   `internal/db/db.go`; sesuaikan untuk bahasa lain), nama package/driver
   yang dipakai, dan cara inject-nya ke layer lain (constructor parameter,
   bukan global variable).

2. "Setup Instance Terbagi Lain" untuk SETIAP komponen relevan di project
   ini: cache client, message queue connection, HTTP client custom, file
   storage client, session store/auth -- masing-masing SATU file
   inisialisasi + SATU instance + inject via constructor. Sebutkan file
   persisnya per komponen. KHUSUS session store: sebutkan eksplisit
   resource mana yang di-reuse sesuai media simpannya (Redis -> reuse
   instance cache client dari step 1; tabel DB -> reuse db_pool dari
   step 1, JANGAN buka koneksi/pool DB kedua khusus session; JWT
   stateless -> tanpa store) -- tidak ada media simpan yang boleh
   melahirkan instance/koneksi baru.

3. "Konvensi Error-Handling" yang mengunci: (a) pola error bahasa tersebut
   (Go: sentinel error di package domain + errors.Is/As + wrap fmt.Errorf
   "%w"; sesuaikan idiom untuk bahasa lain), (b) translasi error layer
   repository -> service -> handler (mana yang jadi 404, 400, 500 sesuai
   format error di API Contracts), (c) error dari driver DB yang dipakai
   (contoh Go+pgx: pgx.ErrNoRows, BUKAN sql.ErrNoRows -- ini bug nyata:
   dua driver berbeda punya sentinel berbeda dan errors.Is tidak match
   silang). Tanpa step ini, tiap issue menebak pola error sendiri.

4. "Setup Config & Logger (Single Source of Truth)": SATU package/struct
   config yang membaca environment/secrets di satu file (sebutkan nama
   filenya persis, sesuai keputusan config management di PRD/Asumsi
   Teknis), dan SATU logger terkonfigurasi di satu file (library persis
   dari PRD/defaults). Semua kode lain membaca config dari struct itu dan
   memakai logger itu via injection -- DILARANG memanggil env-reading
   atau logging-primitive secara langsung di handler/repository, karena
   itu bikin tiap file punya pola config/logging beda (fmt.Println di
   satu package, slog di yang lain, os.Getenv tercecer di handler).

Di SETIAP fase/step berikutnya yang menyentuh database/cache/queue/HTTP
client (repository, handler, worker, dst), WAJIB tulis instruksi eksplisit
"gunakan koneksi/client dari [file Fase 1], JANGAN buat instance/pool
baru" -- ini untuk mencegah coding agent per-issue menebak sendiri dan
berujung ada lebih dari satu instance untuk komponen yang sama.

Di fase yang menyentuh autentikasi/endpoint terproteksi: WAJIB satu titik
verifikasi auth (middleware/dekorator di file spesifik yang kamu sebut
namanya) -- SEMUA endpoint terproteksi lewat titik itu, dilarang implement
pengecekan auth per-handler secara terpisah (konsisten dengan kolom auth
di API Contracts).

Fase TESTING: WAJIB sebutkan strategi test per layer sesuai keputusan
discovery/defaults (library test, testcontainers atau tidak, cakupan
unit/integration/e2e) -- jangan biarkan tiap issue menebak strategi
testing sendiri.
